## Objective

Make domain-descriptor immutability a guarantee the platform registry (`src/platform/domain-registry.js`) enforces itself, rather than a convention each domain package happens to follow.

## Why This Task Exists

Closes the non-blocking finding from Claude's independent review of `P02-T001` (recorded in `docs/tasks/P02/P02-T001.md`'s Review Findings): `createDomainRegistry` freezes only its own `has`/`resolve` interface object, never the domain descriptor objects passed into it. Independently verified during that review — registering an unfrozen test domain and mutating a calculator on it *after* registration caused `resolve()` to return the mutated version. Harmless today because the only registered domain (`pokemonDomain`) self-freezes and there is no dynamic/untrusted domain-loading path yet, but this should be closed before a second domain or any dynamic loading is introduced.

## Dependencies

`P02-T001` — completed, merged to `main` at `2617f4a`.

Independently parallelizable with `P02-T002` — disjoint files (this task touches only `src/platform/domain-registry.js` and its tests; `P02-T002` touches schema/fixture paths). Confirm that remains true before running them concurrently, per `AGENTS.md`'s Parallel Task Planning rule.

## Scope

- `src/platform/domain-registry.js`: freeze (at minimum) each registered domain descriptor object on the way in — `Object.freeze(domain)` — so the registry no longer trusts callers to have done this themselves. Consider whether a deeper freeze (e.g. of `domain.calculators`) is warranted, or whether requiring each domain package to freeze its own nested structures (as `pokemonDomain` already does) is sufficient once the top-level object is frozen by the registry.
- `test/platform-domain-registry.test.js`: add a regression test reproducing the exact gap found in review — register an unfrozen object, mutate a field on the caller's still-held reference after registration, assert the registry's `resolve()` output is unaffected (or that the mutation attempt throws/no-ops, depending on the chosen freeze depth).

## Non-Goals

- No change to `src/domains/pokemon/*` — `pokemonDomain` already self-freezes correctly; this task hardens the platform side, not the existing domain.
- No dynamic/runtime domain loading, no domain-descriptor schema, no second domain — those remain separate future work per `P02-T001`'s Non-Goals.
- No change to the mapping runtime or expression evaluator — unrelated surface.

## Acceptance Criteria

- A domain object registered without being pre-frozen by its own package cannot have its fields mutated (directly or via a caller-held reference) after registration in a way that changes what `resolve()` returns.
- Existing `pokemonDomain` behavior and all currently-passing tests remain green — this is a hardening change, not a behavior change for the one real domain.
- The new regression test fails against the pre-`P02-T003` code and passes after the fix (verify this explicitly, e.g. by confirming it reproduces the gap on `main@2617f4a` before the fix lands).
