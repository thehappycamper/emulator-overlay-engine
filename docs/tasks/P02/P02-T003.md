## Objective

Make domain-descriptor immutability a guarantee the platform registry (`src/platform/domain-registry.js`) enforces itself, rather than a convention each domain package happens to follow.

## Why This Task Exists

Closes the non-blocking finding from Claude's independent review of `P02-T001` (recorded in `docs/tasks/P02/P02-T001.md`'s Review Findings): `createDomainRegistry` freezes only its own `has`/`resolve` interface object, never the domain descriptor objects passed into it. Independently verified during that review — registering an unfrozen test domain and mutating a calculator on it *after* registration caused `resolve()` to return the mutated version. Harmless today because the only registered domain (`pokemonDomain`) self-freezes and there is no dynamic/untrusted domain-loading path yet, but this should be closed before a second domain or any dynamic loading is introduced.

## Implementation Notes

**Design decision — freeze-in-place vs. defensive clone.** Two strategies were considered:

1. **Freeze the caller's descriptor tree in place** (chosen). Simple, no cloning cost, and — critically — preserves the strict object-identity guarantees `P02-T001`'s own tests already depend on: `test/domain-boundary.test.js` asserts `assert.strictEqual(resolveDomain("pokemon"), pokemonDomain)` (the exact same top-level object) and `assert.strictEqual(legacyCalculateCaptureChance, pokemonDomain.calculators.calculateCaptureChance)` (the exact same function reference, proving the `src/engine/*` compatibility shim is a true re-export, not a duplicate implementation). Freezing in place keeps both of those true by construction — the registry stores and returns the identical reference it was given, just no longer mutable.
2. **Deep-clone into an internally-owned structural copy, freeze the copy.** Rejected: this would make `resolveDomain("pokemon") !== pokemonDomain` (a different, cloned object), breaking the existing `strictEqual` test above. Changing that test's semantics was out of scope for this task and would have meant relitigating an already-reviewed, already-merged behavioral guarantee from `P02-T001`.

Freezing an object the caller still holds a reference to is, strictly speaking, a mutation of caller-owned state (per the task's "do not mutate caller-owned objects unexpectedly if avoidable" guidance) — but it's the *documented, intentional point* of this task, not a side effect. It's called out explicitly in the new module comment in `src/platform/domain-registry.js` and in this record, so it's not unexpected/surprising, and for the one real domain (`pokemonDomain`, which already self-freezes) it's a complete no-op in practice — the guarantee only actually starts mutating something the moment a future domain author forgets to self-freeze, which is exactly the case this task exists to cover.

**Design decision — freeze depth.** Rejected two extremes: (a) a shallow `Object.freeze(domain)` only, which the task brief itself flagged as insufficient (`domain.calculators.someCalculator` would still be reachable and mutable); (b) a fully generic deep-freeze framework handling every JS object type, which is more machinery than this boundary needs and could behave surprisingly on object types the registry has no reason to understand (Maps, class instances, etc.). Landed on a bounded recursive freeze restricted to plain objects and arrays — the same "is this JSON-shaped data or something else" distinction `src/mapping/apply.js` and `src/expressions/evaluate.js` already use elsewhere in this codebase (`Object.getPrototypeOf(value) === Object.prototype`) — so the fix is consistent with an established idiom rather than inventing a new one. This freezes however many levels of plain-object/array nesting a descriptor actually has (verified with a 3-level-deep test case), without attempting to freeze functions (which wouldn't meaningfully change their behavior) or exotic objects.

**Circular-reference safety.** The initial implementation incorrectly used `Object.isFrozen()` as both an immutability check and cycle guard. Independent review showed that a shallow-frozen root or intermediate container could therefore hide mutable descendants. The focused fix uses a per-traversal `WeakSet`: eligible containers are marked visited, frozen only when needed, and their children are always traversed on first visit regardless of prior frozen state. Self-cycles, multi-object cycles, and repeated references terminate while preserving identity.

**Top-level descriptor shape.** Domain packages must be structural plain objects. Objects using `Object.prototype` or a null prototype are accepted. Arrays, class instances, and objects with custom prototypes are rejected with `TypeError: Domain packages must be plain objects`. Nested functions and exotic values remain outside the structural-freeze guarantee rather than being generically traversed or frozen.

**Residual recursion-depth limitation.** Traversal remains recursive. Independent review demonstrated that an artificial graph around 20,000 levels deep can exhaust the JavaScript stack. Domains are currently statically imported and repository-reviewed, so this is accepted as non-blocking under the present trust model. Iterative traversal or an explicit depth limit must be reconsidered before untrusted runtime domain installation.

**Verified the tests are meaningful, not padding.** Temporarily reverted the registry fix (`git stash push -- src/platform/domain-registry.js`) and reran the new test file against the original code: multiple tests failed as expected (including the circular-reference and top-level-mutation tests), confirming these are real regression tests. Restored the fix afterward; full suite green again.

## Security/Compatibility Considerations

This task exists entirely because of a defense-in-depth security/robustness finding — see Why This Task Exists. Freeze-in-place remains the explicit ownership contract and preserves descriptor/calculator identity. The guarantee is structural: reachable plain-object/array containers are frozen, while executable behavior, closed-over state, and nested exotic objects remain trusted code. No current code relies on mutating a registered descriptor after registration.

## Review Findings

Independent review returned **REQUEST CHANGES**.

Blocking finding 1: `Object.isFrozen()` was incorrectly used as cycle detection, allowing mutable descendants beneath already-frozen roots or intermediate containers. Fixed with explicit `WeakSet` visitation and regressions for both graph shapes.

Blocking finding 2: class-instance/custom-prototype top-level descriptors were accepted but skipped by the bounded freeze. Fixed by requiring a top-level plain object, explicitly accepting null-prototype objects, and adding deterministic rejection tests.

Non-blocking review findings were also addressed: the platform comment is domain-neutral, documentation now promises structural container immutability rather than arbitrary behavior immutability, and P02-T003 project-status pointers are current. Independent re-review remains pending.

## Result

The platform registry now enforces structural descriptor-container immutability for accepted plain-object domain packages. Explicit graph visitation safely traverses mutable descendants beneath frozen containers and terminates across cycles/shared references. Non-plain top-level descriptors are rejected rather than silently bypassing ownership enforcement. Freeze-in-place and calculator identity remain unchanged.
