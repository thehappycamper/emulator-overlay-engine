## Objective

Establish and document the architectural boundary between this repository (public core) and the new private repository `thehappycamper/gameplay-interaction-hosted-services`, without editing the documentation files another concurrent documentation/product-vision task may be actively using.

## Why This Task Exists

The public repository's product vision has long anticipated an optional future hosted layer ("EOE Cloud" in `docs/knowledge/product-vision.md`). As that vision becomes concrete enough to warrant real implementation work, it needs a private home, and both repositories need to agree — in writing, cross-referenced — on what belongs where before any hosted implementation begins. This is the public-side half of a paired bootstrap; see Related Task below for the private side.

## Dependencies

None within `P02` — this is cross-cutting governance work, not part of the Pokemon domain-boundary objective `P02`'s other tasks pursue, filed under the currently-active phase per this repository's established precedent (e.g. `P01-T008`/`P01-T009` were filed under `P01` for the same reason).

**Related task:** `H00-T001` in `thehappycamper/gameplay-interaction-hosted-services` (branch `chore/H00-hosted-governance-boundary`) — the private-side documentation of this same boundary, developed independently on its own branch in its own isolated clone.
