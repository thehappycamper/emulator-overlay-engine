## Implementation Notes

ADR 0016 records the architectural boundaries but deliberately leaves every public contract and implementation decision deferred. ADR 0014's historical wording remains intact; a clarification marker and ADR 0016 explain that identical game/revision requirements apply only when a selected ruleset requires them.

Maps and progression graphs are explicitly separate: maps describe spatial placement, while progression graphs describe prerequisites and reachability. Cross-domain objective translation is assigned to rules/session logic so source providers and domain events retain their own meaning.

The consistency audit corrected two narrow/ambiguous active descriptions: ADR 0014's same-revision example now points to the ruleset-specific clarification in ADR 0016, and ruleset summaries no longer imply every challenge requires numeric scoring. Searches found no active claim that progress requires manual entry, all games share one formula/coordinate model, maps are Pokemon-only, external workflow tools replace the internal engine, multiplayer requires identical games, one Pokemon game equals one domain, or session score equals player rating.
