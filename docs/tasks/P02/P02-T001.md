## Objective

Introduce the minimum real Pokemon domain package and a domain-neutral resolution boundary. Preserve the existing MVP while proving that shared platform code can remain domain-neutral and Pokemon calculators can be migrated incrementally.

## Why This Task Exists

ADR 0008 established a domain-neutral core with Pokemon as the first domain, but the implemented type chart, damage, projection, and capture logic still lived under the generic-looking `src/engine/` path. P02 needs a concrete, testable dependency direction before further Pokemon schema or UI migration:

```text
Platform Core
      |
Domain Registry / Boundary
      |
Pokemon Domain
```

This task proves that first boundary without attempting the full P02 phase migration.

## Scope

- Add a minimal domain-neutral registry factory.

- Full tests and syntax checks pass.
- Documentation states what moved and what remains deferred.

## Architecture Introduced

`src/platform/domain-registry.js` provides a generic registry factory. It validates package objects and IDs, rejects duplicate IDs, and exposes immutable `has` and `resolve` operations. It imports no domain implementation.

`src/domains/index.js` is the application composition root. It explicitly supplies `pokemonDomain` to the generic registry and exports `resolveDomain`. Pokemon registration belongs here rather than in shared platform code.

`src/domains/pokemon/index.js` is the first domain descriptor and public calculator surface. It exposes stable ID `pokemon` and a frozen calculator collection backed by Pokemon-owned capture, damage/projection, and type-chart modules.

The current overlay resolves `pokemon` through the composition root. Legacy `src/engine/{capture,damage,type-chart}.js` paths re-export the package functions during incremental migration.

## Security/Compatibility Considerations

The registry loads only statically imported, repository-reviewed code; this task introduces no arbitrary code loading or data-driven execution path. Unknown domains throw deterministically. Domain packages and calculator collections are frozen, and no dependency was added.

Compatibility re-exports preserve existing `src/engine/*` imports. They are migration aliases, not shared platform implementations, and should remain until a separately reviewed compatibility decision removes them.
