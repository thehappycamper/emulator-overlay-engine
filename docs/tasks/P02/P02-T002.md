## Objective

Decide and implement the ownership boundary for the Pokemon normalized-state schema: either (a) `overlay-state.schema.json` becomes a thin, domain-neutral envelope (`schemaVersion`, `game`, a `domain` identifier, the top-level `extensions` bag) that `$ref`s a Pokemon-owned payload schema for `player.party[]`/`battle.opponent`, or (b) the schema moves wholesale into `src/domains/pokemon/schemas/` and shared platform code stops referencing it directly. Migrate accordingly, with schema-validation tests updated to match.

## Why This Task Exists

`P02-T001` (`docs/tasks/P02/P02-T001.md`) deliberately deferred this — it moved the Pokemon *calculators* behind a domain boundary but explicitly left `src/schemas/overlay-state.schema.json` in place, with its own Known Limitations section noting "The Pokemon normalized-state schema remains at `src/schemas/overlay-state.schema.json`." `docs/knowledge/domain-extensibility.md` already names this exact open design question (envelope-plus-`$ref` vs. wholesale move) without deciding it. This task decides it and follows through.

## Dependencies

`P02-T001` — completed, merged to `main` at `2617f4a`.

Independently parallelizable with `P02-T003` — the two tasks touch disjoint files (this one touches `src/schemas/`, Pokemon fixtures, and schema-validation tests; `P02-T003` touches only `src/platform/domain-registry.js` and its tests). Confirm that remains true before running them concurrently, per `AGENTS.md`'s Parallel Task Planning rule.

## Scope

- Choose and record the schema-boundary approach (envelope + `$ref`, or wholesale move) — this is itself a decision this task must make, not one handed down in advance.
- `src/schemas/overlay-state.schema.json` (and/or a new `src/domains/pokemon/schemas/*.json`).
- `test/schema-validation.test.js` and any fixtures it validates (`public/sample-state.json`, `examples/extensions/fusion-data-extension/fixtures/*`).
- Update `docs/knowledge/domain-extensibility.md`'s "Pokemon-specific code still outside the package" list once the schema moves.
- `docs/decisions/` — likely warrants an ADR, since this changes a public schema `$id`/structure (per `AGENTS.md`'s ADR rule), unlike `P02-T001` which didn't need one.

## Non-Goals

- No overlay presentation/UI migration (`src/overlay/app.js`'s rendering logic) — separate future work.
- No second domain, no event/action/session work.
- No change to the mapping runtime (`src/mapping/`, `src/expressions/`) — the schema this task touches is a mapping *target* contract, not the mapping mechanism itself.

## Acceptance Criteria

- The chosen schema boundary is documented with rationale (why envelope-vs-move was decided the way it was).
- `npm test` passes, including schema validation against whichever fixtures reference the (possibly relocated) schema.
- If the schema `$id` changes, `src/schemas/template.schema.json`'s cross-reference behavior (if any) and `docs/project/branding-and-renaming.md`'s Category 3 compatibility-sensitive-identifier list are checked for impact.
- Existing overlay behavior (rendering `public/sample-state.json`) is unaffected.
