## Objective

Move ownership of the Pokemon normalized-state contract behind the Pokemon domain boundary while preserving current state payloads, overlay behavior, and source-agnostic platform architecture.

## Why This Task Exists

`P02-T001` moved Pokemon calculators into `src/domains/pokemon/` but deliberately left the Pokemon-shaped state schema under shared `src/schemas/`. That made Pokemon party, battle, move, encounter, and item fields appear platform-owned and would force future domains to inherit an unrelated payload shape. This task closes that ownership gap and implements ADR 0008's domain-schema direction.

## Implementation Notes

Option B, moving the schema wholesale, was selected over a thin platform envelope. The current overlay reads the Pokemon payload directly, while the mapping runtime already identifies opaque named/versioned targets and does not require a universal state wrapper. An envelope would therefore create a breaking and speculative abstraction.

The canonical contract is `src/domains/pokemon/schemas/overlay-state.schema.json`. Its existing schema ID, `https://emulator-overlay-engine.local/schemas/overlay-state.schema.json`, is preserved. `pokemonDomain.stateContract` publishes the matching `pokemon.overlay-state` / `normalized-state` / `0.1.0` descriptor.

`src/schemas/overlay-state.schema.json` has no independent `$id` and delegates to the canonical schema's stable ID with `$ref`. It contains no `properties` or `$defs`, so there is one maintained Pokemon payload schema. The state shape itself is unchanged.

Future Pokemon reuse should compose the Pokemon domain with generation/mechanics, game configuration, and revision/hack/mod overrides. This task records that direction but does not implement those layers. See ADR 0015.

## Review Findings

Claude's independent review of this branch (`feat/P02-T002-pokemon-state-schema-boundary` at `d2c24f1`, in an isolated clone, no files modified) returned **verdict: APPROVE**, with no blocking findings. Summary:

- Confirmed `src/domains/pokemon/schemas/overlay-state.schema.json` is byte-identical to the pre-migration schema (diffed against the exact pre-branch commit) — a pure move, zero content drift.
- Confirmed `src/schemas/overlay-state.schema.json` contains exactly `$schema`/`title`/`description`/`$ref` — no `properties`, no `$defs` — so there is exactly one maintained Pokemon payload definition, not a duplicate.
- Independently verified schema resolution from scratch (a fresh Ajv instance, not reusing the branch's own test harness): registered only the canonical schema, compiled the compatibility shim standalone, and confirmed it correctly validates a known-good fixture and rejects one with a required field removed — same result validating directly against the canonical schema.
- Confirmed `pokemonDomain.stateContract.schema` equals the canonical schema's `$id` exactly, and that `resolveDomain("pokemon").stateContract` is the same object reference the domain module exports (composition layer correctly surfaces it).
- Confirmed `src/platform/`, `src/mapping/`, `src/expressions/`, and all three domain-neutral platform schemas (`extension`, `template`, `mapping`) are completely untouched by this branch, with zero Pokemon-specific field leakage (independently grepped).
- Verified ADR 0015's rejection of a generic state envelope on its factual merits (the mapping runtime's `contractDescriptor.type` genuinely has no platform enum, so a Pokemon-typed target doesn't require a platform wrapper schema to be usable) rather than accepting the ADR's claim at face value.
- Confirmed the future Pokemon composition direction (Domain + Generation/Mechanics + Game Configuration + Revision/Mod Overrides) is not structurally obstructed — the schema already models per-game/revision variance as data, not as separate schemas, and `pokemonDomain`'s flat descriptor shape doesn't assume a single permanent configuration.
- Three non-blocking observations, none requiring a fix here: the schema `$id`'s URI path has no domain-specific segment (a naming quirk inherited from history, not a structural problem — any future second domain just needs its own distinct filename); `pokemonDomain.stateContract` is declared but not yet wired into any actual `validateTarget` call site (correctly out of scope for this task); `extension.schema.json`'s pre-existing `ui.slots` enum includes `"party"` (unrelated to and untouched by this branch).
