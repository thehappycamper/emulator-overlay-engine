# P02-T006: Migrate Pokemon Presentation Ownership

- **Task ID:** `P02-T006`
- **Phase:** `P02` — Domain Boundary (see [implementation plan](../../project/implementation-plan.md))
- **Status:** review
- **Owner:** Codex
- **Branch:** `feat/P02-T006-pokemon-presentation-boundary`
- **Worktree/Clone Isolation:** Fresh independent clone `EOE-P02-presentation-ui`, separate from shared and review checkouts.

## Objective

Move the remaining Pokemon-specific overlay rendering and styling behind the Pokemon domain descriptor while preserving the current static overlay. Remove the hardcoded Pokemon slot vocabulary from the shared extension schema without invalidating existing manifests.

## Why This Task Exists

`P02-T001` through `P02-T003` established calculator, state-schema, and registry ownership, but `src/overlay/app.js` still interprets Pokemon party, battle, capture, move, and encounter fields directly. The shared extension schema also hardcodes the Pokemon-oriented `party` slot. These are the remaining concrete P02 presentation leaks identified by ADR 0008 and `docs/knowledge/domain-extensibility.md`.

## Dependencies

`P02-T001`, `P02-T002`, and `P02-T003` are complete on `main`. This task starts from `main@748f841` and does not depend on future events, actions, source providers, or dynamic extension loading.

## Scope

- Add a minimal domain-neutral overlay presentation dispatcher.
- Move Pokemon field interpretation, calculator use, markup, and domain styles under `src/domains/pokemon/`.
- Expose the Pokemon presentation through `pokemonDomain`.
- Keep `public/index.html` as the explicit application composition point for the Pokemon MVP.
- Replace the shared extension schema's fixed slot enum with validated semantic slot IDs; keep legacy unqualified slot values valid and use qualified Pokemon slots in current examples.
- Add rendering, dispatch, compatibility, and schema regression tests.
- Update the ADR, code map, domain/UI knowledge, feature inventory, implementation plan, and project-memory pointer.

## Non-Goals

- No events, actions, rules, maps, progress, multiplayer, hosted services, Workbench redesign, dynamic domain installation, or live mGBA implementation.
- No generalized panel/plugin framework or runtime extension loader.
- No normalized-state envelope or Pokemon state-schema redesign.
- No removal of `src/engine/*` compatibility re-exports.

## Acceptance Criteria

- Shared overlay infrastructure contains no Pokemon field or calculator assumptions.
- The Pokemon domain owns the current renderer and domain-specific stylesheet.
- The static sample renders equivalent party, opponent, switch-damage, catch, route, score, seed, and frame content through the domain descriptor.
- Generic presentation dispatch works with a non-Pokemon test descriptor and fails deterministically for missing presentation capability.
- Existing unqualified extension slot IDs remain schema-valid; qualified domain slot IDs are supported; the platform schema no longer enumerates `party` or other domain panel names.
- `npm test`, syntax checks, Markdown links, and `git diff --check` pass.
- P02 exit criteria and the next Emerald/mGBA vertical-slice readiness are explicitly audited.

## Implementation Notes

Initial classification:

- **Generic presentation infrastructure:** browser root discovery, state URL selection/loading, domain lookup, stylesheet installation, error display, and invoking a selected presentation capability.
- **Pokemon-specific presentation:** all current markup, party/opponent/encounter field interpretation, capture and switch-damage projections, and layout classes in `public/styles.css`.
- **Compatibility-only:** `src/engine/*` calculator re-exports and unqualified slot IDs already accepted by extension manifests/templates.
- **Genuine remaining leakage:** Pokemon rendering in `src/overlay/app.js` and fixed domain-oriented slot names in `src/schemas/extension.schema.json`.

The intended abstraction is deliberately narrow: a statically registered domain descriptor may expose `presentation.renderOverlay` and `presentation.stylesheets`. This is not a dynamic plugin API or sandbox.

Compatibility review kept `template.schema.json` panel slots as arbitrary strings because narrowing that existing contract would reject previously valid templates. Only `extension.schema.json` changed: its closed Pokemon-oriented enum became a validated semantic identifier, which is a backward-compatible widening for every previously valid extension slot.

## Emerald/mGBA Readiness Audit

Read-only result for the desired `mGBA -> source -> mapping -> Pokemon state/domain -> live overlay` milestone:

Ready now:

- Domain-neutral named/versioned mapping contract and executable safe mapping runtime.
- Canonical Pokemon state contract and domain descriptor.
- Pokemon calculations and presentation behind the domain boundary.
- Browser state URL override (`?state=/public/live-state.json`) and dependency-free static server.
- Configuration placeholders and adapter direction documentation.

Concrete missing pieces:

1. An mGBA Lua source provider that detects supported Emerald revision(s), owns memory addresses, decodes encrypted Gen III Pokemon structures, and emits snapshots safely.
2. A named/versioned Emerald source contract plus representative fixtures. The current adapter folder contains documentation only.
3. An Emerald source-to-Pokemon-state mapping project and orchestration that invokes `applyMappingProject`. The current fusion mapping is unrelated. Raw party arrays/table enrichment may require the source provider to emit already-decoded records or a separately reviewed mapping/data-lookup capability because the current mapper does not iterate and enrich arbitrary arrays.
4. Runtime target-schema resolution/validation wiring for `pokemonDomain.stateContract`; `applyMappingProject` accepts `validateTarget`, but no live pipeline supplies it.
5. A robust live handoff: atomic `live-state.json` writes (or another future transport), error handling for partial/unavailable snapshots, and actual use of `EOE_LIVE_STATE_PATH` (currently documentation only).
6. Continuous overlay refresh. The current browser host loads the selected JSON once and does not poll or subscribe.
7. Emulator/version setup documentation, public-safe decoded source fixtures, mapping/target integration tests, and a manual live mGBA smoke test. No ROM, BIOS, save, or unrestricted memory dump belongs in the repository.

The repository's documented direct-normalized-export exception could bypass item 3, but that would not prove the exact source-to-mapping vertical slice requested for the next milestone.
