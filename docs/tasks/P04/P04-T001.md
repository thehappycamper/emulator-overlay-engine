## Objective

Prove the smallest domain-neutral `semantic event -> declarative rule -> validated action request` path on top of P03.

## Why This Task Exists

P03 established semantic events but no consumer boundary. This slice establishes request-only rules behavior without prematurely adding provider mutation, action execution, or an event bus. See [ADR 0026](../../decisions/0026-rules-to-action-requests.md).

## Dependencies

`P03-T001` semantic event foundation is complete on `origin/main`.

## Scope

The task adds a declarative rule schema and fail-closed validator, bounded event-envelope predicates, a domain-neutral rule evaluator, an action-request schema/validator, and the harmless `overlay.notification` request proof.

## Non-Goals

No action executor, provider capability checks, emulator writes, input injection, savestate control, event bus, scripting runtime, arbitrary JavaScript, plugin execution, visual rule editor, multiplayer, or external integration.

## Acceptance Criteria

- Valid rules and action requests validate against explicit schemas.
- Rules match event type and bounded predicates deterministically.
- Disabled/non-matching/failing rules emit no requests.
- Multiple rules and actions preserve declaration order.
- Every request is validated and carries sequence, correlation, rule, event, and payload data.
- Source events are not mutated and no provider/domain implementation is imported.
- A real P03 `pokemon.fainted` detector event triggers a notification request through generic evaluation.

## Implementation Notes

Predicate paths use safe own-property JSON Pointers. Supported operators are `equals`, `notEquals`, `exists`, `notExists`, `greaterThan`, and `lessThan`; `notEquals` returns false for a missing path so callers must use `notExists` for absence checks. The evaluator currently accepts only `overlay.notification` and requires a string `payload.message`.

## Security/Compatibility Considerations

The evaluator never uses `eval`, `Function`, dynamic imports, provider calls, or host APIs. Action requests are descriptive only. Prototype-sensitive JSON Pointer segments are rejected during resolution. The action schema permits future action types, but this evaluator fails closed for types it does not explicitly support.
