## Objective

Make the real `public/index.html` app shell load through the existing development server and native browser ESM, including the dashboard and notification polling surfaces.

## Why This Task Exists

P04-T003 identified that the production shell failed on the bare `ajv/dist/2020.js` import before the browser could render the overlay. Node resolves the package through npm; a browser cannot resolve npm bare specifiers or execute Ajv's Node/CommonJS entrypoint in a native source-module graph.

## Scope

The Pokemon browser descriptor no longer imports semantic-event detector code. Presentation, state-contract metadata, and calculators remain browser-safe; Node-side event detection continues to import `src/events/derive.js` and Ajv through `src/domains/pokemon/events.js`. The full Node domain descriptor remains unchanged; the browser app resolves a separate browser-safe presentation descriptor.

## Non-Goals

No bundler, frontend framework, schema redesign, event/action behavior, notification feature, emulator integration, or P04-T004 successor work is included.

## Acceptance Criteria

- Real `public/index.html` loads through `tools/dev-server.mjs` without unresolved-module errors.
- Dashboard and independent notification polling render together.
- Notification text remains DOM-safe.
- Node-side event/schema validation and existing behavior remain intact.
- Clean dependency installation and full tests pass.

## Implementation Notes

The browser dependency chain was `app.js -> domains/index.js -> pokemon/index.js -> pokemon/events.js -> events/derive.js -> events/validate.js -> ajv/dist/2020.js`. The fix removes only the event-detector edge from the browser descriptor. The live Emerald orchestrator already imports `pokemon/events.js` directly, so the Node event pipeline remains explicit and unchanged.

## Review Findings

Independent review verdict: **APPROVE**.

**Root-cause diagnosis independently confirmed.** Reproduced the pre-fix failure directly: loading the real `public/index.html` through `tools/dev-server.mjs` on `origin/main` (`0dec811`, before this fix) threw `Failed to resolve module specifier "ajv/dist/2020.js"` in the browser console, and the `#app` root never rendered anything - `resolveDomain("pokemon")` on `domains/index.js` pulls in `pokemon/index.js` → `pokemon/events.js` → `events/derive.js` → `events/validate.js` → the bare npm specifier `ajv/dist/2020.js`, which native browser ESM cannot resolve. A static recursive import-graph walk from `src/overlay/app.js` (12 modules, zero bare specifiers, zero CommonJS `require`/`module.exports`/`exports.` usage) plus a live Chrome network trace (41 requests, all HTTP 200, module set matching the static walk exactly) both confirm `ajv` is no longer reachable from the real browser entry point after the fix.

**Architecture.** `src/domains/browser.js` (a second, browser-safe domain registry built with the same, unmodified `createDomainRegistry` primitive) and `src/domains/pokemon/presentation-descriptor.js` (state-contract metadata, calculators, and presentation only - no `events`) are a sound, minimal boundary correction, not a hidden workaround: `pokemon/index.js` (the full Node domain) now sources its `stateContract`/`presentation`/calculator functions from `presentation-descriptor.js` too, so those specific fields are the *same object references* in both the browser and Node domain descriptors - they cannot silently diverge. The one soft spot is that the `calculators` object literal is constructed twice (once in each file) from the same imported functions; a future calculator addition/removal in one file without the other would go undetected by any current test, since no test directly exercises `src/domains/browser.js`/`pokemonBrowserDomain`'s shape or its parity with the full `pokemonDomain` - only the end-to-end headless-Chrome test (`test/browser-shell.test.js`) touches it, indirectly. This is a real, narrow drift risk, but the current design is sound for this focused fix; recommended as a non-blocking follow-up below rather than requiring a redesign now. No provider/emulator knowledge, no hardcoded `node_modules`/machine-specific paths, and no bundler/framework were introduced (`package.json`/`package-lock.json` are untouched by this commit); `src/events`, `src/rules`, and `src/actions` are byte-for-byte unchanged, and `pokemon/index.js` still exports `pokemonEvents`/`detectPokemonEvents`/`matchPartyMembers`/`pokemonIdentityKey` exactly as before.

**Real browser verification (real `public/index.html`, real `tools/dev-server.mjs`, no substitute harness).** Loaded the actual app shell in Chrome: dashboard rendered fully (team/battle panels, live-status line reading `Live: /public/sample-state.json`), a seeded notification feed rendered alongside the dashboard (not replacing it) with correct info/error severity styling, an `<img onerror=...><script>...</script>` XSS-attempt message rendered as inert literal text with no dialog/script execution, and the console was completely empty (zero errors/warnings) across two page loads. Reloaded once more to verify reconnect stability: the live-status timestamp advanced, both the dashboard and notifications re-rendered correctly, and the console remained clean. The project's own new automated regression (`test/browser-shell.test.js`, real headless Chrome via `--dump-dom` against the real dev server, not a substitute page) was independently confirmed to fail on pre-fix `origin/main` (empty `#app`, no `Live:` status line) and pass reliably (3/3 runs) on this fix.

Semantic-event tests: unchanged, `test/events-derive.test.js`/`test/pokemon-events.test.js` passing. `P04-T003` notification behavior: unchanged, all 54 notification-related tests (`notification-feed`, `write-notification-feed`, `notification-view`, `notification-dom`, `overlay-notification-delivery`, `emerald-live-state-notifications`, `notification-delivery-atomicity`) passing. `P04-T002` capability/replay/executor behavior: unchanged, `test/action-executor.test.js` passing. `test/presentation-boundary.test.js` and `test/domain-boundary.test.js` still exercise real production code (unchanged) and pass.
