## Scope

- A dependency-injectable polling controller (`src/overlay/live-state.js`) that: fetches on a fixed interval without overlapping requests, invokes a render callback only when fetched state actually differs from the last successfully rendered state, and reports a `live`/`stale`/`error` diagnostic status with timestamps.
- Wire the controller into `src/overlay/app.js`, replacing the previous one-shot `loadState()` + single render with continuous polling, while preserving the existing domain-neutral host/dispatch boundary established by `P02-T006`.
- A small, domain-neutral status badge in `public/styles.css`/`app.js`, rendered outside the domain's own content container so diagnostic status stays a platform/host concern, not a Pokemon-presentation concern.
- An optional `data-poll-interval-ms` attribute on `#app` to override the default interval.
- Unit tests for the polling controller's logic, plus a manual/scripted end-to-end smoke run against the real dev server with a changing and deliberately truncated fixture file (not committed; browser automation is unavailable in this environment, consistent with `P02-T006`'s precedent).

## Acceptance Criteria

- The overlay fetches its configured state source repeatedly, re-renders automatically when the fetched state changes, and never issues a second fetch before the previous one settles.
- A missing, non-OK, or invalid/partially-written state response is caught without throwing, without clearing the last successfully rendered content, and is reflected in a `stale` (if prior good state exists) or `error` (if not) status.
- The overlay recovers to a `live` status and re-renders automatically once a valid fetch follows failures.
- Repeated identical state does not cause repeated renders.
- Existing static/sample-state behavior (`public/sample-state.json`, no live source configured) is visually unchanged aside from now polling harmlessly in the background.
- The Pokemon presentation/domain boundary established by `P02-T006` is untouched — `src/domains/pokemon/presentation.js` is not modified, and the new status chrome lives entirely in the domain-neutral host layer.
- `npm test`, `git diff --check`, and Markdown-link validation pass.

## Implementation Notes

`src/overlay/live-state.js` exports `createLiveStateController({ fetchState, onRender, onStatus, intervalMs, now, schedule, cancel, isEqual })`. Non-overlap is structural, not timer-based: the controller only schedules its next fetch inside the `finally` block after the current `fetchState()` promise has settled (success or failure), using a recursive `setTimeout` rather than `setInterval`. `schedule`/`cancel`/`now` are injectable specifically so the unit tests can drive the controller deterministically (a manual scheduler that captures the pending callback and lets the test invoke it) without depending on real timers or any timer-mocking library/API. State-change detection uses `JSON.stringify` structural comparison (`defaultIsEqual`) — a documented, dependency-free approximation that is safe in practice for this use case (a false "changed" positive only costs a harmless extra render; a real change is never missed) but is not a semantic diff and is sensitive to key-order changes from a hypothetical future writer that reorders keys between writes.

`status.phase` is `"error"` only when no fetch has ever succeeded (nothing to show); `"stale"` when the most recent fetch failed but a prior good state exists (last good content stays on screen); `"live"` otherwise. `status.lastUpdatedAt` is the timestamp of the most recent successful fetch; `status.lastErrorAt`/`lastErrorMessage` record the most recent failure for diagnostics.

`app.js` now creates two persistent child elements under `#app` (a `.live-status` badge and a content container) instead of replacing `#app`'s entire `innerHTML` with domain markup on every load. Only the content container's `innerHTML` is replaced on each render; the status badge is updated independently via `dataset.state` (styled in `public/styles.css` by color) and text content. This keeps the split from `P02-T006` intact: `src/overlay/*` remains domain-neutral, and nothing Pokemon-specific was added to it.

Default poll interval is 1000ms, chosen as a conservative, human-perceptible-but-not-wasteful default for a local single-machine proof (not tuned for any specific mGBA export rate, since no live source exists yet). Overridable per page via `data-poll-interval-ms` on `#app`; falls back to the default if absent, non-numeric, or non-positive.

A real end-to-end smoke test was run (not committed) against the actual `tools/dev-server.mjs` and a real file on disk, using the controller's real `fetch()`-based `loadState()` exactly as `app.js` uses it: initial load, an HP-changing rewrite, an identical rewrite, a deliberately truncated/partial JSON write (`{"hp": 7, "note": "trunc`, simulating a writer interrupted mid-write), and a recovery write. Observed exactly the expected sequence: render → no extra render on identical content → real `JSON.parse` `SyntaxError` ("Unterminated string in JSON...") caught, status `stale`, no render, no crash → recovery render, status back to `live`. This is the same class of failure a real mGBA exporter writing `live-state.json` non-atomically could produce, so this test is directly relevant despite not using mGBA.
