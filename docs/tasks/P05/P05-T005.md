## Objective

Provide a gitignored machine-local configuration and a Windows-friendly setup/launcher for the existing Emerald plus mGBA Proof 1 pipeline.

`P05-T001` through `P05-T004` completed the local source-to-overlay code path, but operators still had to reproduce several path assignments and directory commands manually. This task removes that setup friction without changing acquisition, mapping, normalized state, or overlay behavior.

## Implementation Notes

The launcher uses a narrow Node parser rather than adding `dotenv` or evaluating shell syntax. It supports comments, optional `export`, and quoted/unquoted literal values; it performs no variable expansion. Matching process-environment values override the file, and unrelated config keys are not copied into the structured proof config.

The launcher deliberately starts only mGBA. It does not manage long-running mapper/server children or automate mGBA UI actions. The spawned mGBA process inherits `EMERALD_SOURCE_SNAPSHOT_PATH`; commands printed for separate terminals explicitly set mapper/server variables because a child process cannot mutate a future terminal's environment.

No ADR was added: this is a scoped developer workflow over existing P05 contracts, not a platform/public-contract architecture decision.

## Security/Compatibility Considerations

Config is parsed as data and never evaluated or interpolated. Required local files are read-only inputs to setup validation. The launcher does not inspect or copy ROM/save content. Output directories are created only after all configured paths validate. Existing `.env` usage remains available; `.env.local` is the focused Proof 1 convention.

The launcher passes the configured ROM as the sole mGBA argument and leaves optional savestate/script loading manual. Operators should close an existing mGBA process first so the launched process inherits the snapshot environment.
