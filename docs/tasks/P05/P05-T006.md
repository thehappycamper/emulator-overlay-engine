## Objective

Reduce `P05-T005`'s Emerald Proof 1 launcher to the least-manual *supported* mGBA acquisition path, after investigating what mGBA actually supports for external attachment or automatic bootstrap versus what still genuinely requires manual GUI interaction.

## Why This Task Exists

`P05-T005` deferred both savestate loading and Lua-script loading to manual mGBA GUI steps, citing "an assumed savestate/script CLI" as something it deliberately avoided assuming. This task investigated mGBA's actual documented capabilities rather than continuing that assumption, and found the savestate half of that caution was unnecessary.

## Investigation

Researched mGBA's official documentation, GitHub issue tracker, and command-line reference (not assumed):

- **Script auto-loading has no supported path.** [mgba-emu/mgba#3289](https://github.com/mgba-emu/mgba/issues/3289) — "Command line flag to automatically load script?" — was explicitly **closed as "not planned"** by the mGBA maintainers (milestone `mGBA 0.11.0`, labeled `port:Qt`, `severity:enhancement`). The official [scripting API docs](https://mgba.io/docs/scripting.html) confirm scripts are loaded only via the Tools menu; the Lua `socket` library lets an *already-loaded* script make outbound TCP connections, it is not a mechanism for external attachment or remote script loading. No config-file key for this was found either.
- **Savestate loading does have a supported path.** `mgba-qt` officially documents `-t statefile` / `--savestate statefile` — "Load initial game state from statefile" — confirmed via the [Ubuntu manpage](https://manpages.ubuntu.com/manpages/focal/man6/mgba-qt.6.html) and the synopsis `mgba-qt [-123456fg] [-b biosfile] [-C option=value] [-l loglevel] [-p patchfile] [-s n] [-t statefile] file`. A related old GUI-menu savestate bug ([#2123](https://github.com/mgba-emu/mgba/issues/2123), mGBA 0.9.0) is unrelated to this flag and if anything supports the CLI path being the more reliable one historically ("The `-t` flag loads savestates successfully from the command line, but the same files fail when loaded through mgba-qt's GUI interface").
- ROM loading was already automated by `P05-T005` (positional argument) and is unaffected.

## Scope

- `createMgbaLaunch` in `tools/emerald-proof-config.mjs` appends `--savestate <path>` to mGBA's launch arguments when `EOE_EMERALD_SAVESTATE` is configured; omits it entirely otherwise.
- `tools/launch-emerald-proof.mjs`'s printed instructions updated to reflect automated savestate loading, cite the upstream "not planned" issue for why script loading alone remains manual, and mention **Tools > Scripting... > Load recent script** as a faster one-click reload for returning sessions.
- Documentation (adapter README, `docs/project/configuration.md`, root `README.md`, `.env.local.example`) updated to match.

## Non-Goals

- No change to Lua-script loading — confirmed to have no supported non-GUI path.
- No GUI automation of any kind (keystroke/window automation remains explicitly out of scope, per the original launcher's own constraint).
- No change to source contract, mapping, normalized state, or the overlay.
- No change to which three processes the launcher does or doesn't start — that scope question (raised as a non-blocking note in `P05-T005`'s review) is untouched here.
- No mutation of mGBA's own config file (e.g. to pre-seed "recent scripts") — this isn't a documented/supported mechanism, and mutating a third-party application's config format carries real corruption risk for an unconfirmed benefit; out of scope for a "least-manual *supported*" path.

- The real launcher, run end-to-end, passes this flag to the actual spawned child process (verified directly, not just via unit test).
- Printed instructions accurately describe savestate loading as automatic and script loading as the one remaining manual step, with the upstream issue cited as evidence rather than an unexplained assertion.
- `--check` mode's messaging remains accurate (it describes the mechanism, not a completed launch).
- Full `npm test`, `node --check`, `git diff --check`, and Markdown-link validation pass.

## Review Findings

Independent review completed by Codex on 2026-08-08 with verdict **APPROVE** and no blocking findings.

- Verified against the exact upstream mGBA `0.10.3` tag (`1c61b542`): `src/feature/commandline.c` defines `-t`/`--savestate`, `doc/mgba-qt.6` documents loading an initial state, and the Qt window loads the pending state after core startup.
- Verified the upstream Windows `getopt_long` implementation permutes options after a positional ROM, so `[ROM, "--savestate", STATE]` is accepted by the supported Windows Qt build.
- Independently reproduced child-process argument handling with ROM, config, output, and savestate paths containing spaces. The child received the ROM and exact two-element savestate option/value pair without shell parsing.
- Independently reproduced the no-savestate path and confirmed no flag is emitted.
- Independently reproduced a missing configured savestate and confirmed validation exits nonzero before spawning the child.
- Confirmed upstream issue `mgba-emu/mgba#3289` remains closed as not planned and official scripting documentation still directs users through **Tools > Scripting...**; documentation correctly leaves Lua loading manual.
- Confirmed the branch changes only launcher/config tests and documentation. Acquisition, mapping, schemas, Lua provider, normalized state, and overlay behavior are unchanged.
