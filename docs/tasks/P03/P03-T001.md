## Objective

Implement the first provider-neutral semantic event derivation layer: a domain-neutral primitive that compares two consecutive, already-validated normalized-state snapshots and runs domain-owned detector functions over them, plus the first concrete detector set (Pokemon), proving `P03`'s exit criterion end-to-end.

## Why This Task Exists

Closes `P03`'s phase gate per [ADR 0013](../../decisions/0013-semantic-events-as-platform-primitive.md) and the implementation plan's `P03` exit criteria: "A normalized event contract exists (schema); at least one concrete state-transition-to-event detection is proven end-to-end with tests... no arbitrary-code-execution path introduced." ADR 0013 explicitly deferred the event schema and detector API to "a separately approved vertical slice" — this task is that slice. See [ADR 0024](../../decisions/0024-semantic-event-derivation.md) for the concrete design decision this task implements.

## Dependencies

`P01` (mapping/target-descriptor contract) complete. Does not depend on `P04` (event routing/actions), `P05`, or `P06` — reads only the already-existing canonical `pokemon.overlay-state` schema, not any specific provider's acquisition output.

## Scope

- New domain-neutral platform module `src/events/`: `schemas/event-envelope.schema.json` (the generic envelope contract), `validate.js` (Ajv2020 strict-mode validation, fail-closed), `derive.js` (`deriveEvents`, `createEventSequencer`).
- New Pokemon-domain detector module `src/domains/pokemon/events.js`: ten detectors (`battle.started`, `battle.ended`, `pokemon.hp.changed`, `pokemon.damaged`, `pokemon.healed`, `pokemon.fainted`, `pokemon.status.changed`, `party.changed`, `location.changed`, `badge.earned`), plus `pokemonIdentityKey`/`matchPartyMembers` as the party-slot/opponent identity strategy.
- `src/domains/pokemon/index.js` extended with a new `events` capability (`{detect, detectors}`), mirroring the existing `calculators`/`presentation` capability shape.
- New tests: `test/events-derive.test.js` (platform primitive), `test/pokemon-events.test.js` (Pokemon detectors, including the user-specified transition/dedup/simultaneous-change/battle-entry-exit/party-reorder/initial-snapshot/provider-neutral scenarios).
- `docs/decisions/0024-semantic-event-derivation.md` (new ADR).

## Non-Goals

- No event bus, subscription model, transport, or persistence — `P04`.
- No rules engine, action schema, or emulator-action execution path — `P04` and later product tracks.
- No coupling to BizHawk, mGBA, or Libretro — event derivation reads only normalized state, never raw memory or a specific provider's acquisition output. Verified by an automated import-path test, not just a design intention.
- No change to any existing acquisition, mapping, schema, or presentation behavior — this is a purely additive new capability.
- No attempt to make `pid`-based identity real for the live Emerald provider (that provider does not populate it today) — this task documents the limitation and builds the fallback, it does not close it.

## Acceptance Criteria

- A generic, domain-neutral event envelope schema exists with at minimum: event type, timestamp/sequence, subject/entity reference (nullable), previous/current values (nullable), and provenance.
- `deriveEvents` accepts two normalized-state snapshots and a detector array; never imports or assumes anything BizHawk/mGBA/Libretro-specific.
- All ten specified Pokemon event types are detected where the canonical schema supports them.
- HP `4→0` fires `pokemon.fainted` exactly once; a subsequent `0→0` snapshot pair fires nothing.
- A first-ever snapshot (no previous state) fires nothing, even if already mid-battle with a full party.
- Feeding the identical state twice (value-equal, not reference-equal) fires nothing.
- Party-slot identity is not assumed permanent by index; the real, currently-available identity signal and its limitations are explicitly documented in code and tested.
- Deterministic tests cover: transitions, deduplication, simultaneous changes, battle entry/exit, party reorder/change, initial snapshot behavior, and provider-neutral identical-state behavior.
- Full repository `npm test` passes with zero regressions.

## Implementation Notes

**Envelope shape.** `type` (dotted, lowercase, domain-namespaced string), `sequence` (monotonic integer, guarantees total order even when multiple events share one `detectedAt`), `detectedAt` (ISO 8601 wall-clock detection time — explicitly documented as not tied to any emulator frame counter), `subject`/`previous`/`current` (each `object | null`, domain-defined shape), and `provenance` (`{domain, detector, game?}`). Both `sequence` and `detectedAt` are included, since the user's requirement named "timestamp/sequence" and the two serve genuinely different purposes (total ordering vs. wall-clock reference) rather than being redundant.

**Fail-closed validation.** `assertValidEvent` throws `EventValidationError` (wrapping Ajv's `errorsText`) on any schema violation. `deriveEvents` calls this on every single event a detector emits, before appending it to the result — a detector that emits a malformed partial event (e.g. missing required provenance) throws immediately rather than silently passing a broken event through. This surfaced a real gap during test-writing: several early test fixtures omitted `provenance.domain` and correctly failed closed, which led to adding a dedicated test proving that exact failure mode is intentional, not accidental.

**Deduplication is structural, not bookkept.** No detector tracks "have I already fired this." Each `deriveEvents` call is pure over exactly the two snapshots it receives; feeding the same pair (or a `0→0` pair) twice produces no new information to detect a transition from, so nothing fires. This was proven with `structuredClone`d fixtures to rule out the trivial case of reference-equality short-circuiting.

**Party-slot and opponent identity — read before trusting `subject.slot`.** `pokemonIdentityKey(pokemon)` returns `pid:${pid}` when the canonical schema's optional `pid` field is a non-empty string, else falls back to `heuristic:${speciesId}:${nickname}`. Re-verified directly against the real, current source before designing this (not assumed from memory): `adapters/pokemon-emerald-us-rev0/emerald-us-rev0.js`'s `decodeGen3Pokemon()` reads `personality` internally for decryption/gender derivation but never includes it in the returned object, and `emerald-us-rev0-to-pokemon-overlay-state.mapping.json` has no `pid` mapping entry at all — so every real live provider today falls back to the heuristic key. This fallback is disclosed, not hidden: two individuals of the same species with the same (or no) nickname are indistinguishable by this key, and a species change (evolution) is read as the old individual leaving and a new one arriving, never as a continuous transition of one individual. `matchPartyMembers()` uses slot position only as a same-key tiebreaker (oldest previous-slot match consumed first, FIFO) to preserve relative order for ambiguous duplicates — never as the primary identity signal, and `party[0]` specifically is never treated as permanent identity anywhere in this module. If a provider populates `pid` in the future, matching upgrades automatically with no detector code changes.

**Ambiguous fallback identity policy.** Repeated species+nickname fallback keys are marked ambiguous and excluded from per-Pokemon transition comparisons rather than FIFO-paired. This conservative policy suppresses uncertain HP, damage, healing, faint, and status events instead of fabricating one individual's transition for another. They remain available for party-delta reporting.

**Opponent identity applies the same rule.** HP/status/faint detection on the battle opponent only fires when `pokemonIdentityKey(previousOpponent) === pokemonIdentityKey(currentOpponent)`, so a trainer's fainted Pokemon being replaced by their next one (battle stays active in both snapshots, but it is a different individual) does not fabricate a heal or a status change across two different individuals. Directly tested.

**`party.changed` carries a delta, not a before/after scalar.** Since there is no single coherent "previous value" for a multi-member membership diff, `current` holds `{added, removed, reordered}` and `previous` is `null`. Fires only on membership/order changes; a pure per-member stat change with unchanged membership/order is already covered by the hp/status/fainted detectors and does not also fire `party.changed` (tested explicitly to catch double-reporting).

**`location.changed` does not special-case any fallback string.** It fires on any change to `location.name`, including transitions to/from an acquisition layer's own disclosed "Unknown location" fallback text, to avoid coupling this module to a different layer's magic string.

**Provider-neutrality is enforced by a test, not just a claim.** `test/pokemon-events.test.js` reads the raw source text of `src/events/derive.js`, `src/events/validate.js`, and `src/domains/pokemon/events.js` and asserts no import statement's path matches `adapters/bizhawk`, `adapters/gen3-mgba`, or `experiments/libretro`. An earlier, cruder version of this test did a blunt case-insensitive word match instead, which produced a false positive against `derive.js`'s own comment disclosing the absence of such coupling ("...knows nothing about Pokemon, Emerald, BizHawk, mGBA..."); fixed to check actual import-path coupling, which is the real property that matters.

## Tests Required

- Envelope validation: accepts a well-formed event; rejects empty type, non-lowercase-dotted type, additional properties, and missing provenance.
- `deriveEvents`: returns `[]` without invoking any detector when previous or current state is nullish (proven via a detector that throws if called); correctly stamps `type`/`sequence`/`detectedAt`/`provenance`; flattens multiple detectors' results in order; keeps `sequence` monotonic across multiple calls sharing one sequencer; fails closed on a detector emitting an envelope-invalid event (including one missing required provenance); rejects a non-array `detectors` argument and non-function individual detectors; treats a `null`/`undefined` detector return as no events.
- Pokemon detectors: provider-neutrality (import-path scan); first-ever snapshot emits nothing even mid-battle with a full party; identical state fed twice emits nothing; HP decrease fires `hp.changed`+`damaged` only; HP increase fires `hp.changed`+`healed` only; `4→0` fires `fainted` exactly once across a 5-snapshot sequence and never again on subsequent `0→0` pairs; simultaneous faint+damage+status-change in one snapshot fires all applicable events together; `battle.started`/`battle.ended` fire only on real opponent-appear/disappear transitions; a trainer's next Pokemon replacing a fainted opponent mid-battle does not fabricate a heal/damage; pure party reorder fires no hp/fainted/status events and is reported as `party.changed` with a `reordered` entry; party add/remove reports `party.changed` with `added`/`removed`, and matched members' own transitions still fire normally; unchanged membership+order with changed stats does not fire a spurious `party.changed`; `status.changed` treats a missing status as `"none"`; `location.changed` fires on any name change including transitions to/from a literal fallback string; `badge.earned` fires once per newly-true badge index and never re-fires, and does not fire when badges are unavailable on either side; `pokemonIdentityKey` prefers a real `pid` over the heuristic when present; `matchPartyMembers` documents (via test) its real best-effort limitation for duplicate species+nickname individuals; an evolution is read as old-leaves/new-arrives.

## Security/Compatibility Considerations

No arbitrary-code-execution path: detectors are plain JavaScript functions supplied by the calling domain package at the source-code level, not loaded from user input, a manifest, or a mapping expression — there is no new dynamic-evaluation surface, consistent with `P01-T004`'s existing no-`eval`/no-`Function` constraint. The envelope schema is additive-only relative to existing contracts (it is a wholly new schema, not a change to `pokemon.overlay-state` or any mapping/target schema), so no existing acquisition, mapping, or presentation behavior changes. `assertValidEvent`'s strict Ajv mode and `additionalProperties: false` mean a detector cannot leak arbitrary extra fields into a published event.

## Result

`src/events/` provides a domain-neutral `deriveEvents(previousState, currentState, detectors, options)` primitive and a generic, versioned-by-convention event envelope schema. `src/domains/pokemon/events.js` provides the first concrete detector set, proving all ten specified event types against the real canonical Pokemon schema, with party-slot and opponent identity handled via a documented, tested, forward-compatible heuristic rather than a false claim of permanent slot identity. `P03`'s exit criterion (a normalized event contract, at least one concrete state-transition-to-event detection proven end-to-end with tests, no arbitrary-code-execution path) is met.
