## Most recent session (2026-08-16)

[`P04-T003`](../tasks/P04/P04-T003.md) gives `overlay.notification` a real local delivery path, completing `pokemon.fainted -> declarative rule -> validated action request -> capability-gated executor -> overlay.notification -> local overlay delivery -> browser` end to end, documented in [ADR 0029](../decisions/0029-overlay-notification-local-delivery.md). A second, independent local file-and-poll channel (`public/notifications.json`, via `src/overlay/notification-feed.js`/`write-notification-feed.js`) was chosen over folding notifications into `public/live-state.json`'s own `extensions` field, specifically because that would have forced a full dashboard re-render on every notification - exactly the "replacing the dashboard" outcome ruled out by the task. The browser side reuses `createLiveStateController` unchanged for a second poll loop; a pure reconciliation function (`notification-view.js`) decides what's newly visible vs. expired/dismissed, and every notification DOM node is built with `textContent` only - a structural, not conventional, guarantee against HTML/script injection. Replay/duplicate protection needed no new mechanism: since the real delivery sink only runs inside the executor's own `execute()`, `P04-T002`'s existing replay guarantee already makes a duplicate action request structurally incapable of publishing a second notification (verified with the real provider/executor/feed, not fakes). All real wiring lives in `tools/emerald-live-state.mjs` (the one place already allowed to import a Pokemon domain module for its own composition), which also gained a proper ESM main-module guard it previously lacked entirely; `tools/proof-emerald-bizhawk.mjs` needed zero changes since it already spawns that script as a child process. A CLI smoke against the real fixture confirmed a live HP-to-zero edit produces a real `notifications.json` write; a real Chrome browser smoke confirmed rendering, ordering, severity styling, inert XSS-attempt text, dismiss-persists-across-polls, and expiry-removes-the-node - all working correctly. A pre-existing, unrelated bug was found and disclosed (not fixed, not introduced by this task): loading the real `index.html`/`app.js` directly in a browser fails on `ajv/dist/2020.js`'s bare module specifier, present unchanged on `origin/main` since `P03-T001`; the browser smoke used a small temporary, deleted-after-use harness page to work around it for this task's own deliverables. `npm test`: 355/356 passing (312 baseline + 44 new tests across 6 new test files), 1 pre-existing skip. Implemented, pushed to `feat/P04-T003-overlay-notification-delivery`, and stopped for independent review per explicit instruction - not merged.

A focused fix round then closed a transactional-publication gap: the original `createNotificationDelivery` mutated the in-memory feed before attempting the durable write, so a write failure left a notification committed in memory despite the action reporting failure, and a retry (P04-T002 never caches a non-`"executed"` outcome) would publish a duplicate on top of it; a delayed failed write could even overwrite a newer successful write's file contents. Fixed with commit-after-success: `notification-feed.js` gained a two-phase `prepare()` (compute the next state without mutating) / `commit()` (apply it) pair, and `createNotificationDelivery` now writes the candidate durably before ever committing it, plus a small local serialization queue closes a theoretical concurrent-publish race without a new locking subsystem. All four scenarios were independently verified against the pre-fix code first (three failed directly; the concurrency one revealed a genuine torn-write race on the persisted file specifically) before confirming the fix resolved them. `npm test` scoped to this project's own suite: 323/323 passing, 0 skipped. An unrelated, pre-existing flake in the experimental `experiments/libretro-provider/` package's test suite was independently confirmed present on a clean `origin/main` worktree with no P04-T003 changes at all - out of scope, not investigated further. Pushed on the same branch and stopped for independent re-review - not merged.

## Prior session (2026-08-09), part 1

[`P03-T001`](../tasks/P03/P03-T001.md) implements `P03`'s first concrete slice, per [ADR 0013](../decisions/0013-semantic-events-as-platform-primitive.md)'s deferred vertical-slice requirement, and closes the phase: a domain-neutral `src/events/deriveEvents()` primitive (generic event envelope schema, fail-closed Ajv2020 validation, injectable monotonic sequencer) plus the first concrete detector set in `src/domains/pokemon/events.js` (`battle.started`, `battle.ended`, `pokemon.hp.changed`, `pokemon.damaged`, `pokemon.healed`, `pokemon.fainted`, `pokemon.status.changed`, `party.changed`, `location.changed`, `badge.earned`), documented in [ADR 0024](../decisions/0024-semantic-event-derivation.md). The task's central design problem was party-slot identity: re-verifying the real, current Emerald acquisition source confirmed no live provider today populates the canonical schema's optional `pid` field, so `pokemonIdentityKey`/`matchPartyMembers` prefer `pid` when present but fall back to a documented species+nickname heuristic. Independent review round 1 returned REQUEST CHANGES: repeated fallback identities were FIFO-paired rather than treated as non-comparable, which could fabricate a per-Pokemon transition attributed to the wrong individual, and the envelope's `detectedAt` field had no real format validation despite being documented as ISO 8601 (any non-empty string passed). Both were fixed on `fix/P03-T001-event-review-findings`: ambiguous fallback keys (occurring more than once on either side of a transition) are now marked non-comparable and excluded from per-Pokemon HP/damaged/healed/fainted/status detection - conservatively suppressing an uncertain transition rather than guessing which individual it belongs to - while unambiguous identities, `pid`-backed identities, and party membership/reorder reporting are unaffected; the schema's `detectedAt` now enforces a real ISO 8601/RFC3339-shaped pattern. Round 2 independent review (39 adversarial probes beyond the committed suite, covering duplicate reordering, partial ambiguous-pair changes, ambiguous add/remove, pid-collision immunity, and opponent-identity conservatism) returned **APPROVE**; fast-forward merged, closing `P03`.

[`P05-T013`](../tasks/P05/P05-T013.md) introduces the first isolated Libretro provider boundary: native core loading, ABI checks, callbacks, memory-map discovery, bounded region-relative reads, frame execution, structured errors, and deterministic shutdown run in a child process (`experiments/libretro-provider/`) behind a local versioned JSON-lines protocol, documented in [ADR 0025](../decisions/0025-libretro-child-process-provider.md). Independent review found one blocking finding: the child's `readline` line handler dispatched each request as an independent `async` callback with no serialization. The focused fix adds a strict FIFO promise-chain queue and synchronous shutdown admission gate; independent re-review approved the fix. P05-T013 remains an isolated provider seam, not production Libretro readiness.

[`P04-T002`](../tasks/P04/P04-T002.md) adds the capability-gated action executor `P04-T001` deliberately stopped short of: `src/actions/execute.js`'s `createActionExecutor()` runs every request through a fail-closed pipeline (registered provider → granted capability → per-request authorization → valid payload → execute), returning a schema-validated `ActionResult` for every outcome and never throwing, documented in [ADR 0027](../decisions/0027-capability-gated-action-executor.md). Capability is deliberately decoupled from action type (a provider's `requiredCapability` need not equal its `actionType`), proven by independently granting only one of two proof providers' capabilities and confirming the other is rejected `MISSING_CAPABILITY` even though it is registered. Two harmless local providers - `overlay.notification` and `system.log` - prove the architecture with injectable, no-real-I/O-by-default sinks. Replay/duplicate handling uses a full canonical request fingerprint, single-flights concurrent and synchronous re-entrant duplicates, clears failed reservations, and contains malformed provider failures as structured results. `src/rules/evaluate.js` was not modified and has no import coupling with the new executor in either direction. Final validation passed with 307 tests and 2 pre-existing skips; the task was independently approved and merged to `main` at `5da3ee4`.

A focused fix round then strengthened the executor: replay identity moved from a bare `correlationId:sequence` pair to a full canonical fingerprint (`actionType`, `correlationId`, `sequence`, `ruleId`, `triggeringEvent`, `payload`), an in-flight single-flight guard now ensures exactly one provider invocation occurs even when concurrent identical requests race each other (later/concurrent callers receive the same outcome as `duplicate` without re-invoking the provider, and a failed in-flight attempt never deadlocks or poisons the key), and every thrown-value/malformed-return edge case is normalized into a structured result instead of ever escaping `execute()`. A final microtask reservation fix closed synchronous provider re-entry before any pipeline code begins. See the updated [ADR 0027](../decisions/0027-capability-gated-action-executor.md) and [`P04-T002`](../tasks/P04/P04-T002.md)'s task record for the full design and review history. Final validation passed with 307 tests and 2 pre-existing skips; P04-T002 was independently approved and merged at `653b61e`.

The final focused review specifically confirmed the synchronous re-entrancy fix: deferring `runPipeline(...)` to a microtask reserves `inFlight` before any provider code runs. An independent no-`authorize()` provider probe observed exactly one invocation, an outer `executed` result, a re-entrant `duplicate` carrying the same result, and a later exact `duplicate`. The branch was approved and merged at `653b61e`; P04 remains active.

`P05-T007` is an independent feasibility spike testing whether EOE can directly host the mGBA libretro core (no RetroArch, Lua, GUI automation, or process hooking), following up on prior Libretro/RetroArch research. Using Node.js plus a prebuilt-binary FFI library (no C compiler is available in this environment) against the real, officially-redistributed mGBA libretro core, it verified dynamic core loading, full callback registration, and `retro_init` work correctly, and that a rejected (non-ROM) `retro_load_game()` call is handled safely. No valid Emerald ROM was available in this environment, so `retro_load_game()` never succeeded and `retro_run()`, `SET_MEMORY_MAPS`, and a live memory read were never reached or observed - honestly documented as the specific, unresolved blocker rather than assumed or implied. Two independent-review fix rounds since corrected the address-translation algorithm, FFI decode path, first-descriptor precedence, and cleanup/fail-closed behavior. Recommendation: promising, continue as a small independent prototype track alongside (not instead of) the mGBA/BizHawk work, once that live-ROM gate is closed.

`P05-T006` investigated mGBA's actual documented capabilities rather than continuing to assume none existed: confirmed via the mGBA maintainers' own "closed as not planned" resolution of [mgba-emu/mgba#3289](https://github.com/mgba-emu/mgba/issues/3289) that Lua-script auto-loading has no supported non-GUI path, but found `mgba-qt` officially documents a `--savestate` command-line flag that `P05-T005` wasn't using. Independent review verified the exact mGBA 0.10.3 parser, Windows option permutation, Qt load path, paths-with-spaces argument handoff, optional behavior, and fail-before-spawn validation; verdict APPROVE and fast-forward merged.

`P05-T005` adds a non-executable `.env.local` parser, path/setup validation, output-directory preparation, and `npm run proof:emerald`. Independent review directly proved environment inheritance by running the launcher against a real Node.js stand-in for mGBA that reported its own inherited environment (not just unit tests), confirmed gitignore coverage by creating real `.env.local`/`.env.*.local` files, and confirmed `--check` mode never spawns a process; verdict APPROVE, two disclosed non-blocking notes (a Node.js launcher rather than PowerShell, and only mGBA is auto-launched rather than all three processes), merged by fast-forward.
