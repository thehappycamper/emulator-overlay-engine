## Most recent session (2026-08-09)

[`P05-T012`](../tasks/P05/P05-T012.md) replaces the three-terminal BizHawk proof workflow (`npm run proof:bizhawk` + `npm run live:emerald` + `npm start`, each hand-coordinated) with a single `npm run proof:emerald:bizhawk` session command. Split into a reusable, emulator-agnostic orchestration primitive (`tools/proof-session.mjs` - ordered spawn gated on per-child readiness, `[label]`-prefixed log streaming, real port-availability checking, PID-based coordinated termination, no Pokemon/Emerald knowledge) and a small BizHawk-specific composition that reuses `bizhawk-proof-config.mjs`'s config/launch logic and the existing mapper/server scripts completely unmodified (documented in [ADR 0023](../decisions/0023-proof-session-orchestrator.md)). A real end-to-end CLI smoke test (not just the exported-function unit tests) caught a genuine Windows-specific bug before review: the "is this the main module" guard used string-concatenated `file://` comparison, which never matches `process.argv[1]`'s Windows-style path, so the CLI entry point silently never ran (no error, exit code 0) - fixed with `pathToFileURL()`.

[`P05-T009`](../tasks/P05/P05-T009.md) (independently reviewed, APPROVE, and merged) turns the prior single-slot Proof 2 overlay into a real team/battle dashboard: acquisition now decodes every occupied party slot's full encrypted record (nickname, gender, status, EXP, held item, moves-with-PP, individual stats/IVs - previously only species/level/HP/one substruct were read), a new game-owned reference-data layer (generated from real `pret/pokeemerald` source, not typed from memory) resolves species/move/item/location names, and the presentation layer is rewritten as a six-slot team grid plus a separate battle panel. The mapping and target schema were extended as the smallest principled change (loosened `move`'s required fields, added optional fields) rather than redesigned, documented in [ADR 0021](../decisions/0021-emerald-live-dashboard-and-reference-data.md). Review also exercised the Lua port live against BizHawk with the real ROM as a connector smoke. A separate, narrowly-scoped developer-only live memory/data explorer (`P05-T008`, pushed on its own `feat/P05-T008-emerald-memory-explorer` branch, not yet merged) was built first to accelerate this work.

Two further, parallel enrichment tasks followed, each on its own branch from `origin/main` post-`P05-T009`, and both are now independently reviewed and merged. [`P05-T010`](../tasks/P05/P05-T010.md) adds a collapsible battle stat comparison panel using only `P05-T009`'s already-decoded fields (no new acquisition/schema work), and investigated but deferred battle stat-stage/active-battler-slot decoding (no verifiable fixed memory address for the relevant runtime battle-engine structures in this offline environment). [`P05-T011`](../tasks/P05/P05-T011.md) adds real wild-encounter-rate display and a live, state-aware Poke Ball catch-odds panel, using the Gen III catch-rate formula transcribed directly from `pret/pokeemerald`'s `Cmd_handleballthrow` (documented in [ADR 0022](../decisions/0022-encounter-rates-and-catch-odds.md)); ball types whose real bonus depends on undecoded state (Dive/Repeat/Timer/Safari Ball) are marked unavailable rather than guessed, and the catch-odds panel only ever renders during an explicitly confirmed wild (non-trainer) battle. `P05-T011` was rebased onto `origin/main` after `P05-T010`'s merge, resolving overlapping presentation-layer changes while preserving both features. `P05-T011`'s independent review re-verified every acquisition/formula claim against a fresh `pret/pokeemerald` source fetch and independently reproduced several catch-probability calculations from scratch, all matching the implementation to full floating-point precision; one non-blocking documentation citation (Master Ball's exact guaranteed-catch mechanism) was strengthened during review. Both tasks' Lua ports remain disclosed as untested (no Lua interpreter available in this environment).

## Prior session (2026-08-08)

`P06-T002` establishes `pokemon.emerald.us-rev0.acquisition@1.0.0` under a game-owned adapter, moves shared Emerald addresses/Gen III decoding/schema/fixtures/mapping out of mGBA ownership, and makes mGBA and BizHawk thin providers for the same contract. BizHawk now verifies every known System Bus read against the translated direct EWRAM/IWRAM domain before atomic publication. The existing mapper, Pokemon state validation/domain, live-state handoff, and overlay remain the only downstream path. Independent review re-derived the Gen III decryption math by hand and verified BizHawk's memory-domain claims against real tagged BizHawk source; verdict APPROVE, one disclosed non-blocking finding, merged.

`P05-T007` is an independent feasibility spike testing whether EOE can directly host the mGBA libretro core (no RetroArch, Lua, GUI automation, or process hooking), following up on prior Libretro/RetroArch research. Using Node.js plus a prebuilt-binary FFI library (no C compiler is available in this environment) against the real, officially-redistributed mGBA libretro core, it verified dynamic core loading, full callback registration, and `retro_init` work correctly, and that a rejected (non-ROM) `retro_load_game()` call is handled safely. No valid Emerald ROM was available in this environment, so `retro_load_game()` never succeeded and `retro_run()`, `SET_MEMORY_MAPS`, and a live memory read were never reached or observed - honestly documented as the specific, unresolved blocker rather than assumed or implied. Two independent-review fix rounds since corrected the address-translation algorithm, FFI decode path, first-descriptor precedence, and cleanup/fail-closed behavior. Recommendation: promising, continue as a small independent prototype track alongside (not instead of) the mGBA/BizHawk work, once that live-ROM gate is closed.

`P05-T006` investigated mGBA's actual documented capabilities rather than continuing to assume none existed: confirmed via the mGBA maintainers' own "closed as not planned" resolution of [mgba-emu/mgba#3289](https://github.com/mgba-emu/mgba/issues/3289) that Lua-script auto-loading has no supported non-GUI path, but found `mgba-qt` officially documents a `--savestate` command-line flag that `P05-T005` wasn't using. Savestate loading is now automated via that flag; script loading remains manual. Independent review verified the exact mGBA 0.10.3 parser, Windows option permutation, Qt load path, paths-with-spaces argument handoff, optional behavior, and fail-before-spawn validation; verdict APPROVE and fast-forward merged.

`P05-T005` adds a non-executable `.env.local` parser, path/setup validation, output-directory preparation, and `npm run proof:emerald`. The launcher passes source snapshot configuration into the new mGBA child, starts the configured ROM, and prints manual savestate/Lua plus mapper/server commands. It does not automate mGBA GUI actions, inspect/copy game assets, or change source/mapping/runtime contracts. Independent review directly proved environment inheritance by running the launcher against a real Node.js stand-in for mGBA that reported its own inherited environment (not just unit tests), confirmed gitignore coverage by creating real `.env.local`/`.env.*.local` files, and confirmed `--check` mode never spawns a process; verdict APPROVE, two disclosed non-blocking notes (a Node.js launcher rather than PowerShell, and only mGBA is auto-launched rather than all three processes), merged by fast-forward.

`P05-T004` adds the checked-in mapping from `pokemon.emerald.us-rev0.mgba.acquisition@1.0.0` to `pokemon.overlay-state@0.1.0`, uses explicit placeholders for unavailable required fields, validates the canonical target through `applyMappingProject()`, and atomically publishes `public/live-state.json` through `npm run live:emerald`. Independent review hand-traced the mapping's placeholder/collapse logic, independently reproduced its output, independently proved fail-closed behavior end-to-end via the real CLI against a corrupted source (byte-identical output file before/after), and independently proved the mapped output renders safely through the real Pokemon renderer; verdict APPROVE, no blocking findings, merged by fast-forward. This completes the initial local source-to-overlay code path; real mGBA smoke and broader phase-gate fields remain before `P05` can close.

`P05-T001` replaced the overlay's one-shot state load with a domain-neutral polling controller that prevents overlapping fetches, renders only changed JSON-derived state, preserves the last good render through missing/truncated state files, and reports `live`/`stale`/`error`. Independent review reproduced HP changes, truncated-JSON staleness, recovery, and default sample-state rendering against the real controller/dev-server path; verdict APPROVE, no blocking findings. Its integration was reconciled with the concurrently completed `P05-T002` acquisition proof.

`P02-T006` (earlier session) moved Pokemon markup, state interpretation, calculator-backed projections, and styles into the Pokemon package, closing `P02` — Domain Boundary.
